# Ручне тестування Visual Novel Engine

Цей документ описує базову перевірку Visual Novel Engine на ПК у браузері. Android-збірки, емулятори та тестування на телефоні не входять у поточний обсяг робіт.

Перед початком запустіть застосунок за [інструкцією для Windows](TESTER_QUICK_START.md).

## Дані тесту

| Поле                       | Значення                               |
| -------------------------- | -------------------------------------- |
| Дата і час                 |                                        |
| Версія або commit          | результат `git rev-parse --short HEAD` |
| Windows                    |                                        |
| Браузер і версія           |                                        |
| Роздільна здатність екрана |                                        |
| Результат                  | Пройдено / Є помилки / Заблоковано     |

Не використовуйте приватний режим браузера. Якщо тест потребує очищення даних сайту, спочатку експортуйте важливі історії.

## Позначення результатів

- **PASS** — фактичний результат відповідає очікуваному.
- **FAIL** — функція працює неправильно або застосунок показує помилку.
- **BLOCKED** — перевірку неможливо продовжити через іншу проблему.
- **SKIPPED** — перевірка свідомо не виконувалася; вкажіть причину.

## 1. Запуск і головна сторінка

1. Запустіть `corepack pnpm dev:web`.
2. Відкрийте <http://localhost:8081>.
3. Дочекайтеся завершення завантаження бібліотеки.
4. Перейдіть у **Settings / Налаштування** і перевірте перемикання мови, якщо воно доступне.
5. Поверніться на головну сторінку.

Очікуваний результат:

- немає червоного екрана, порожньої сторінки або нескінченного завантаження;
- демоісторії відображаються без дублікатів;
- кнопки **Studio** та налаштувань реагують;
- після зміни мови основні написи оновлюються.

## 2. Перегляд демоновели

1. На головній сторінці відкрийте одну з демоісторій.
2. Запустіть читання та пройдіть кілька реплік.
3. Зробіть доступний вибір.
4. Якщо сцена містить звук, ефект або перехід, дочекайтеся його відтворення.
5. Поверніться назад і знову відкрийте історію.

Очікуваний результат:

- фон, персонажі, текст і кнопки не перекривають одне одного;
- репліки переходять у правильному порядку;
- вибір веде до відповідної гілки без зависання;
- аудіо та візуальні ефекти не блокують керування;
- повернення з reader не ламає навігацію.

## 3. Створення нової історії

1. Натисніть **Studio**.
2. Створіть історію з назвою `Тестова новела`.
3. Відкрийте сторінку створеної історії.
4. Заповніть автора й короткий опис, якщо ці поля доступні.
5. Перейдіть до **Редагувати новелу / Edit novel**.

Очікуваний результат:

- історія створюється один раз;
- введені назва, автор і опис показуються без спотворень;
- українські символи зберігаються правильно;
- редактор відкриває сцену цієї, а не іншої історії.

## 4. Редагування сцени

1. Додайте або змініть текст першої сцени.
2. Додайте щонайменше одну репліку персонажа.
3. Створіть другу сцену.
4. Додайте вибір або перехід між сценами, якщо відповідний інструмент доступний.
5. Відкрийте preview поточної сцени.

Очікуваний результат:

- введений текст не зникає після зміни фокуса;
- сцени показуються у правильному порядку;
- preview відповідає вмісту активної сцени;
- вибір або перехід веде до визначеної сцени;
- помилки однієї дії не руйнують весь документ.

Якщо певний тип блоку ще не готовий у поточній збірці, позначте його як **SKIPPED** і вкажіть причину.

## 5. Reader для створеної історії

1. Поверніться на сторінку історії.
2. Натисніть **Переглянути новелу / Play novel**.
3. Пройдіть створений текст до другої сцени та перевірте вибір.
4. Поверніться в редактор і змініть одну репліку.
5. Знову відкрийте reader.

Очікуваний результат:

- reader використовує останню збережену версію сцен;
- текст і вибори відповідають редактору;
- зміна у редакторі з'являється після повторного запуску reader;
- reader не відкриває демоісторію замість тестової.

## 6. Локальне збереження

1. Запам'ятайте останню зміну у `Тестовій новелі`.
2. Оновіть сторінку через `Ctrl+R` і перевірте історію у Studio.
3. Повністю закрийте вкладку браузера.
4. Відкрийте <http://localhost:8081> знову у тому самому профілі браузера.
5. Перевірте історію повторно.

Очікуваний результат:

- історія, сцени та останні зміни залишилися після оновлення;
- дані залишилися після закриття й повторного відкриття вкладки;
- демоісторії не продублювалися.

Втрата даних у цьому сценарії є критичною помилкою. Не очищайте сховище браузера до збереження діагностичної інформації.

## 7. Експорт

1. На сторінці тестової історії знайдіть дію експорту або повної резервної копії.
2. Запустіть експорт і підтвердьте попередження, якщо воно з'явиться.
3. Перевірте, що браузер завантажив файл і він має ненульовий розмір.

Очікуваний результат:

- експорт завершується повідомленням про успіх;
- браузер завантажує файл;
- назва файлу дозволяє пов'язати його з історією;
- застосунок продовжує працювати після експорту.

Імпорт перевіряйте лише тоді, коли в поточному інтерфейсі є явна дія імпорту. Не очищайте наявні дані заради цієї перевірки.

## 8. Базова стійкість інтерфейсу

Повторіть основний сценарій при ширині вікна приблизно 1440 px, 1024 px і 768 px.

Очікуваний результат:

- основні кнопки залишаються доступними;
- текст не виходить за межі панелей;
- сторінку можна прокрутити до всіх дій;
- модальні вікна можна закрити;
- фокус клавіатури видно у текстових полях.

## Що не входить у поточний цикл

- Android Studio, Android-емулятори й установлення на телефон;
- iOS, Xcode і native build-команди;
- Supabase та cloud backup, якщо їх окремо не налаштували;
- платні AI-провайдери та їхні ключі, якщо їх окремо не надали;
- перевірка опублікованої Android-версії готової новели.

## Як оформити повідомлення про помилку

Одна проблема — один звіт. Назва має коротко описувати фактичну поведінку, наприклад: `Після Ctrl+R зникає друга сцена`.

```text
Назва:

Середовище:
- commit:
- Windows:
- браузер і версія:
- роздільна здатність:

Передумови:

Кроки відтворення:
1.
2.
3.

Очікуваний результат:

Фактичний результат:

Частота:
- завжди / іноді / один раз

Вкладення:
- скриншот або відео
- текст помилки з PowerShell
- помилка з консолі браузера, якщо доступна
```

Не додавайте до звіту API-ключі, pairing token, вміст `.env` або інші секрети.
