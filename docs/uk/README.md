# Visual Novel Engine

[English project page](../../README.md)

Visual Novel Engine — це редактор і програвач інтерактивних візуальних новел. Тут можна написати історію, розділити її на сцени, додати персонажів, фони й музику та побудувати сюжет, який змінюється залежно від рішень читача.

Робота починається з тексту. Ви пишете сцену як документ, а потім додаєте потрібні дії: появу персонажа, зміну фону, звуковий ефект або вибір наступного кроку. Результат можна переглядати прямо в редакторі, а всю історію — запускати в режимі читання.

Для базової роботи не потрібні обліковий запис чи підключення сторонніх сервісів. Проєкти зберігаються локально у браузері. Інтерфейс доступний українською та англійською.

## З чого почати

**[Встановлення та запуск на Windows](INSTALLATION.md)** — повна інструкція від встановлення Git і Node.js до відкриття редактора. Містить команди PowerShell, перевірки після кожного етапу, повторний запуск, оновлення та вирішення типових проблем.

**[Створення першої новели](USER_GUIDE.md)** — невелика історія з персонажем, фоном і двома сюжетними шляхами. Ви перевірите обидва варіанти та збережете повну резервну копію.

**[Налаштування програми](SETTINGS.md)** — пояснення параметрів звуку й читання, локального збереження та додаткових інтеграцій.

Інструкція описує запуск із вихідного коду: сервер працює на вашому комп’ютері, а ви користуєтеся програмою у браузері. Для цього потрібні Node.js 24 або новіший та pnpm 10.23.0. Android-інструменти й ключі сторонніх сервісів для такого запуску не потрібні.

## Що можна створювати

Редактор поєднує оповідь і діалоги з візуальними та звуковими діями. Можна почати зі звичайного тексту й поступово додавати оформлення.

| Можливість | Для чого вона потрібна |
| --- | --- |
| Історії та сцени | Упорядкування проєктів і написання сцен як документів. |
| Оповідь і діалоги | Поєднання описових уривків із розмовами персонажів. |
| Вибори та переходи | Створення різних шляхів розвитку сюжету. |
| Змінні та умови | Запам’ятовування рішень і використання їх у наступних сценах. |
| Фони та спрайти персонажів | Оформлення місця подій і показ персонажів. |
| Музика, голос та звукові ефекти | Звуковий супровід історії. |
| Ефекти, переходи й камера | Постановка важливих моментів сцени. |
| Інтерактивні об’єкти | Взаємодія читача з елементами сцени. |
| Попередній перегляд і читання | Перевірка окремої сцени та всієї історії. |
| Імпорт, експорт і повні копії | Збереження роботи та перенесення між пристроями. |
| Версії випусків | Фіксація версії історії для поширення. |
| Додаткові AI та хмарне резервування | Підключення сторонніх можливостей за потреби. |

У [посібнику користувача](USER_GUIDE.md) можна спробувати основний процес на невеликому прикладі. [Довідник дій англійською](../technical/block-types-reference.md) описує окремі типи дій та їхні поля.

## Комфортне читання

У налаштуваннях можна вибрати мову інтерфейсу, окремо відрегулювати музику, голос та ефекти, змінити швидкість появи тексту й розмір тексту діалогів. Для читача є окремі параметри масштабу шрифту та міжрядкового інтервалу.

Автовідтворення, паралакс і фонове відео також мають власні перемикачі. [Довідка налаштувань](SETTINGS.md) пояснює, на що вони впливають. Налаштування AI-провайдерів описане окремо в [інструкції AI bridge англійською](../../tools/ai-bridge/README.md).

## Збереження роботи

Локальні історії належать до профілю браузера та адреси, де ви їх створили. Вони не з’являються автоматично в іншому браузері чи на іншому комп’ютері. Очищення даних сайту може видалити їх, а приватний режим — втратити після закриття сеансу.

Автозбереження допомагає продовжувати роботу між сеансами. Для перенесення створюйте **повну резервну копію** зі сторінки проєкту: вона містить історію та медіафайли. JSON-експорт містить структуру історії без зображень і звуку. Робіть повні копії перед оновленнями й великими змінами та використовуйте одну вкладку редактора: одночасні зміни сцен не можна безпечно об’єднати.

Докладніше — у [кроці про резервні копії](USER_GUIDE.md#7-збережіть-повну-копію).

## Поширення готової історії

Випуск фіксує одну версію новели. Після цього можна редагувати чернетку, не змінюючи вже випущену історію. [Інструкція з випусків англійською](../technical/releases.md) пояснює підготовку самостійної вебверсії.

[Пакування для комп’ютера](../technical/releases-desktop.md) та [Android](../technical/releases-android.md) мають окремі інструкції англійською й додаткові вимоги. Для створення новели у браузері ці інструменти встановлювати не потрібно.

## Стан проєкту та допомога

Проєкт активно розвивається. Документований обсяг перевірки охоплює редактор і читач у браузері на ПК, вебпакет та локально зібрану Windows-оболонку. Шлях збірки Android через EAS реалізований, але перевірка платної збірки й роботи на реальному пристрої ще не завершена. Додаткові інтеграції потребують окремого налаштування.

При проблемах із запуском почніть із [вирішення типових помилок](INSTALLATION.md#типові-проблеми). Якщо помилка повторюється, [створіть issue](https://github.com/9ThLen/Visual-Novel-Engine/issues): опишіть кроки, очікуваний і фактичний результат та додайте відповідне повідомлення про помилку.

## Для розробників

Проєкт використовує Expo, React Native Web, TypeScript, Zustand, NativeWind та Plate. Активний редактор сцен розташований у `src/components/editor/plate/`; канонічна модель даних — `SceneRecord + TimelineStep`.

Після встановлення залежностей доступні команди:

```powershell
pnpm.cmd dev:web  # Запуск у браузері
pnpm.cmd check    # Перевірка TypeScript
pnpm.cmd test     # Модульні тести
pnpm.cmd lint     # Перевірка лінтером
```
