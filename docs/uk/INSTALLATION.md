# Встановлення та запуск Visual Novel Engine на Windows

[Опис проєкту](README.md) · [Перша новела](USER_GUIDE.md) · [Налаштування](SETTINGS.md) · [English](../en/INSTALLATION.md)

Ця інструкція проведе вас від підготовки Windows-комп’ютера до відкриття редактора. Досвід програмування не потрібен. Виконуйте команди по черзі й чекайте завершення кожного кроку.

## Що саме ви запускатимете

Ви завантажите вихідний код і запустите локальний сервер розробки. Редактор відкриється у браузері, а сервер працюватиме у вікні PowerShell. Це встановлення з вихідного коду, а не через Windows-інсталятор програми.

Для завантаження інструментів і залежностей потрібен інтернет. Базовий локальний редактор не потребує облікового запису, AI-ключа, Supabase чи файлу `.env`. Android Studio та Java для цього способу запуску також не потрібні.

## 1. Встановіть Git і Node.js

1. Завантажте [Git for Windows](https://git-scm.com/download/win), запустіть інсталятор і залиште стандартні параметри.
2. На сайті [Node.js](https://nodejs.org/en/download) завантажте Windows-інсталятор **Node.js 24 LTS**. Встановіть Node.js разом із пакетним менеджером npm. Мінімальна версія Node.js для проєкту — 24.
3. Для роботи з програмою використовуйте Chrome, Edge або Firefox.

Після встановлення закрийте відкриті термінали. Відкрийте меню **Пуск**, введіть **PowerShell** і запустіть його. Звичайного вікна достатньо: команди проєкту не потребують запуску від адміністратора.

Перевірте встановлені інструменти:

```powershell
git --version
node --version
npm.cmd --version
```

Кожна команда має показати номер версії. Результат Node.js повинен починатися з `v24` або новішої підтримуваної версії. Якщо команда не знайдена, закрийте й повторно відкрийте PowerShell, а потім повторіть перевірку.

## 2. Підготуйте pnpm

Проєкт використовує pnpm 10.23.0 для встановлення залежностей. Встановіть цю версію через npm:

```powershell
npm.cmd install --global pnpm@10.23.0
pnpm.cmd --version
```

Друга команда має вивести `10.23.0`. У цій інструкції використовуються команди з `.cmd`, щоб політика виконання сценаріїв PowerShell не блокувала пакетний менеджер.

Якщо ви вже користуєтеся Corepack, можна замінити `pnpm.cmd` на `corepack pnpm`. Налаштовувати обидва способи не потрібно.

## 3. Завантажте проєкт

Виберіть папку для вихідного коду. Наприклад, ці команди створять папку Projects у вашій папці користувача Windows і відкриють її:

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\Projects"
Set-Location "$env:USERPROFILE\Projects"
```

Тепер завантажте репозиторій:

```powershell
git clone https://github.com/9ThLen/Visual-Novel-Engine.git
Set-Location Visual-Novel-Engine
```

Git створить папку `Visual-Novel-Engine`, а друга команда відкриє її в PowerShell. Збережіть цю папку: ви повертатиметеся до неї для запуску й оновлення.

Перевірте, що відкрили правильне місце:

```powershell
Test-Path package.json
```

Результат має бути `True`. Якщо ви вже завантажили репозиторій, відкрийте наявну папку замість повторного клонування.

## 4. Встановіть залежності

У папці проєкту виконайте:

```powershell
pnpm.cmd install
```

Перше встановлення може тривати кілька хвилин. Не закривайте PowerShell під час завантаження. Можуть з’являтися попередження; дочекайтеся завершення команди. Успішне встановлення повертає запрошення PowerShell без повідомлення про невдале встановлення.

Якщо сталася помилка, усуньте її перед запуском програми. Зазвичай цей крок повторюють після оновлення проєкту, а не перед кожним відкриттям.

## 5. Запустіть програму

Виконайте:

```powershell
pnpm.cmd dev:web
```

Зачекайте запуску сервера та завершення початкової збірки для браузера. Якщо вкладка не відкрилася автоматично, самостійно перейдіть на [http://localhost:8081](http://localhost:8081).

Ви маєте побачити головний екран програми. Залишайте PowerShell відкритим під час роботи: саме він обслуговує програму у браузері. Закриття вікна зупиняє сервер.

Щоразу використовуйте той самий профіль браузера й адресу. Дані прив’язані до них: інший браузер, порт або заміна `localhost` на `127.0.0.1` можуть створити враження, що ваші історії зникли.

## 6. Перевірте редактор і читач

1. Відкрийте студію з головного екрана.
2. Відкрийте одну з демонстраційних історій.
3. Запустіть її для читання та перейдіть через кілька реплік.
4. Поверніться до історії й відкрийте редактор.

Якщо історія відкривається та відтворюється, налаштування завершене. Переходьте до [створення першої новели](USER_GUIDE.md). Назви кнопок залежать від мови інтерфейсу; в англійській версії студія називається **Studio**, а запуск історії — **Play novel**.

## 7. Завершіть роботу та запустіть знову пізніше

Перед завершенням дочекайтеся закінчення збереження. У PowerShell натисніть **Ctrl+C**. Якщо термінал запитає про завершення пакетного завдання, підтвердьте його.

Наступного разу відкрийте PowerShell і виконайте:

```powershell
Set-Location "$env:USERPROFILE\Projects\Visual-Novel-Engine"
pnpm.cmd dev:web
```

Якщо ви вибрали іншу папку, вкажіть власний шлях. Знову відкрийте [http://localhost:8081](http://localhost:8081). Для звичайного повторного запуску не потрібно клонувати проєкт або перевстановлювати залежності.

## 8. Оновіть програму

Спочатку створіть **повні резервні копії** важливих історій на їхніх сторінках проєкту. Текстовий JSON-експорт не містить зображень і звуку. Збережіть завантажену копію поза сховищем браузера.

Зупиніть сервер через **Ctrl+C**, а потім у папці проєкту виконайте:

```powershell
git pull --ff-only
pnpm.cmd install
pnpm.cmd dev:web
```

Переходьте до наступної команди лише після успішного завершення попередньої. Коли сервер буде готовий, оновіть сторінку браузера.

Якщо Git повідомляє про локальні зміни або неможливість fast-forward, зупиніть оновлення та збережіть повідомлення. Не скидайте репозиторій і не видаляйте зміни заради примусового оновлення. Історії зберігаються у браузері, але ваші зміни вихідного коду також потрібно зберегти.

## Типові проблеми

### Команда не знайдена

Закрийте PowerShell, відкрийте його знову та повторіть перевірки з першого кроку. Якщо Git або Node.js досі не знайдені, повторіть встановлення й перевірте додавання до PATH. Якщо бракує лише pnpm, повторіть другий крок і перезапустіть PowerShell.

### PowerShell забороняє виконання сценаріїв

Використовуйте `npm.cmd` і `pnpm.cmd`, як у прикладах, замість `npm` і `pnpm`. Для цих команд не потрібно змінювати системну політику виконання сценаріїв.

### Непідтримувана версія Node.js

Виконайте `node --version`. Встановіть Node.js 24 LTS, відкрийте нове вікно PowerShell, перевірте версію та повторіть `pnpm.cmd install`.

### Залежності не встановлюються

Перевірте інтернет і скопіюйте перше повне повідомлення `ERR_PNPM`. Якщо проблема стосується мережі, перевірте налаштування проксі чи VPN та повторіть спробу після відновлення доступу. Не видаляйте проєкт і не очищайте дані браузера для виправлення встановлення.

### Порт 8081 уже зайнятий

Перевірте, чи програма вже працює в іншому вікні PowerShell. Скористайтеся тим екземпляром або зупиніть його через **Ctrl+C** перед новим запуском. Для звичайної роботи залишайте порт 8081, щоб повертатися до того самого сховища браузера.

### Браузер не підключається

Перевірте, що сервер досі працює в PowerShell і не завершився з помилкою. Відкрийте `http://localhost:8081` вручну. Якщо сервер зупинився, запустіть його з папки проєкту.

### Сторінка показує стару версію

Спочатку натисніть **Ctrl+Shift+R**. Якщо це не допомогло, зупиніть сервер і запустіть його з очищенням кешу збірки:

```powershell
pnpm.cmd exec expo start --web --port 8081 --clear
```

Це очищає кеш збірки для розробки. Не очищайте дані сайту у браузері: так можна видалити історії.

### Історії зникли

Перевірте початкові браузер, профіль та адресу. Не використовуйте приватний режим для роботи, яку хочете зберегти. Якщо дані браузера вже видалені, відновіть збережену резервну копію через імпорт у студії.
