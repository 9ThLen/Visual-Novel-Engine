# Швидкий запуск для тестувальника на Windows

Ця інструкція допоможе вперше запустити Visual Novel Engine на ПК у браузері. Досвід програмування не потрібен.

## Що саме ви запускатимете

Visual Novel Engine працюватиме локально на вашому комп'ютері як web-застосунок. Ви створюватимете, редагуватимете та перевірятимете новели у браузері.

Для цього тестування **не потрібні** Android Studio, Android-емулятор, Java, телефон, обліковий запис Supabase, `.env` або API-ключі. Android поки розглядається лише як майбутня платформа для читання готової новели.

## 1. Встановіть необхідні програми

Потрібні лише:

1. [Git for Windows](https://git-scm.com/download/win) — залиште стандартні параметри інсталятора.
2. [Node.js LTS](https://nodejs.org/en/download) — використовуйте LTS-версію, не Current. Мінімальна підтримувана версія для Expo SDK 54 — Node.js 20.19.
3. Chrome, Edge або Firefox останньої доступної версії.

Після встановлення Git і Node.js закрийте та повторно відкрийте PowerShell.

## 2. Перевірте інструменти

Відкрийте меню **Пуск**, введіть `PowerShell` і запустіть Windows PowerShell. Виконайте по черзі:

```powershell
git --version
node --version
corepack pnpm --version
```

Кожна команда має показати номер версії. Під час першого запуску Corepack може попросити завантажити pnpm — погодьтеся. Цей проєкт використовує pnpm 10.23.0.

Якщо PowerShell пише, що команда не знайдена, перейдіть до розділу [Типові проблеми](#типові-проблеми).

## 3. Завантажте проєкт

У тому самому PowerShell виконайте:

```powershell
git clone https://github.com/9ThLen/Visual-Novel-Engine.git
cd Visual-Novel-Engine
```

Перша команда створить папку `Visual-Novel-Engine`, друга — відкриє її в PowerShell.

Якщо репозиторій уже завантажений, не клонуйте його повторно. Відкрийте його папку командою `cd`, наприклад:

```powershell
cd C:\Users\ВашеІм'я\Visual-Novel-Engine
```

## 4. Встановіть залежності

Виконайте:

```powershell
corepack pnpm install
```

Процес може тривати кілька хвилин. Попередження жовтого кольору не завжди означають помилку. Встановлення завершилося успішно, якщо команда повернула запрошення PowerShell без червоного повідомлення `ERR_PNPM`.

Цю команду не потрібно виконувати перед кожним запуском. Повторіть її після отримання оновлень проєкту.

## 5. Запустіть застосунок

Виконайте:

```powershell
corepack pnpm dev:web
```

Не закривайте це вікно PowerShell. Коли сервер буде готовий, браузер зазвичай відкриється автоматично. Якщо цього не сталося, відкрийте вручну:

<http://localhost:8081>

Успішний результат:

- сторінка Visual Novel Engine завантажилася без червоного екрана помилки;
- видно головну сторінку з демоісторіями та кнопкою **Studio**;
- після натискання **Studio** відкривається бібліотека редактора.

Перший запуск може тривати довше через підготовку web-збірки.

## 6. Зупиніть і запустіть повторно

Щоб зупинити застосунок, поверніться у PowerShell, де працює сервер, і натисніть `Ctrl+C`. Якщо PowerShell запитає про завершення процесу, підтвердьте його.

Щоб запустити застосунок наступного разу:

```powershell
cd C:\шлях\до\Visual-Novel-Engine
corepack pnpm dev:web
```

Повторно виконувати `git clone` не потрібно.

## 7. Отримайте оновлення

Спочатку зупиніть сервер через `Ctrl+C`, потім у папці проєкту виконайте:

```powershell
git pull
corepack pnpm install
corepack pnpm dev:web
```

Ваші новели зберігаються у даних браузера, а не у файлах Git. Проте перед значним оновленням рекомендується експортувати важливу історію через інтерфейс застосунку.

## Дані та приватність

- Без додаткової конфігурації дані зберігаються локально у поточному браузері.
- Інший браузер або інший профіль браузера матиме окреме сховище.
- Режим InPrivate/Incognito може видалити дані після закриття вікна — не використовуйте його для звичайного тестування збереження.
- Очищення даних сайту для `localhost` може видалити створені історії.
- `.env`, Supabase й AI-ключі для базового тестування не потрібні.

## Типові проблеми

### `git` або `node` не знайдено

Переконайтеся, що відповідну програму встановлено. Закрийте всі вікна PowerShell, відкрийте нове й повторіть перевірку версії. Якщо проблема залишилася, перезавантажте Windows.

### `corepack` не знайдено

Переконайтеся, що встановлена LTS-версія Node.js із офіційного інсталятора. Повторно відкрийте PowerShell і виконайте `node --version`.

### Помилка доступу під час завантаження pnpm

Перевірте інтернет-з'єднання, VPN, proxy або корпоративний антивірус. Повторіть `corepack pnpm --version`.

### `ERR_PNPM` під час встановлення

Збережіть повний текст першої помилки. Перевірте версію Node.js і повторіть `corepack pnpm install`. Не видаляйте файли або папки проєкту без узгодження з розробником.

### Порт 8081 уже використовується

Перевірте інші вікна PowerShell: можливо, застосунок уже запущений. Зупиніть старий процес через `Ctrl+C` і повторіть запуск.

### Сторінка не відкривається

Переконайтеся, що PowerShell із сервером залишається відкритим і не показує помилку. Відкрийте <http://localhost:8081> вручну та виконайте жорстке оновлення через `Ctrl+Shift+R`.

### Застосунок показує стару версію

Зупиніть сервер, виконайте `git pull`, а потім запустіть із очищенням кешу:

```powershell
corepack pnpm install
corepack pnpm exec expo start --web --port 8081 --clear
```

### Windows Firewall запитує дозвіл

Для запуску лише на цьому ПК достатньо дозволити Node.js доступ у приватній мережі. Доступ у публічних мережах не потрібен.

## Що надіслати розробнику при помилці

Надішліть:

- номер кроку, на якому виникла проблема;
- повний текст помилки з PowerShell;
- скриншот браузера;
- версії з `git --version`, `node --version` і `corepack pnpm --version`;
- назву та версію браузера;
- версію Windows;
- короткий опис того, що ви очікували побачити.

Після успішного запуску переходьте до [сценарію ручного тестування](MANUAL_TESTING.md).
